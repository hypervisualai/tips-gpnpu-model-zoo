# fuse_scale_v1 — scale.json 형식

모델 패키지의 `scale.json` 형식이다. JSON Schema 는 같은 폴더의 [`fuse_scale_v1.schema.json`](fuse_scale_v1.schema.json).

문장 끝의 **"해야 한다"·"안 된다"는 지켜야 하는 규칙**이고, "권장"은 지키지 않아도 틀린 파일은 아니다.

## 1. 무엇을 담는 파일인가

GPNPU 의 NPU 에서 모델을 INT8 로 돌릴 때 필요한 **층별 활성값 범위**와, **NPU 에서 빼고 부동소수점(FP)으로 계산할 층 목록(FP 유지 층)**을 담는다.

- scale 파일 하나는 **가중치 파일 하나와 입력 해상도 하나**에만 맞는다. 둘 중 하나라도 바뀌면 값을 다시 재서 새 파일을 만든다
  - 예: 같은 yolo26n 구조라도 coco 가중치·320, coco 가중치·640, drone 가중치·320 은 파일이 각각 따로다
  - 읽는 쪽은 가중치(`weights.sha256`)나 해상도(`imgsz`)가 지금 실행과 다르면 오류를 낸다(§6.3)

담지 않는 것

| 담지 않는 것 | 있는 곳 |
|---|---|
| 가중치, 가중치 스케일, bias 보정 | 가중치 파일. 이 파일은 `weights.sha256` 으로 그 파일을 가리키기만 한다 |
| 층 연결 관계 | 모델 구조 |
| 범위를 스케일로 바꾸는 계산(반올림·재양자화 배율) | 실행하는 쪽 |
| 활성값 비대칭(zero-point) | v1 에 없다 |

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 층 | 모델 안의 `nn.Conv2d` 또는 `nn.Linear` 모듈 하나 |
| 루트 모듈 | 층 이름의 기준이 되는 모델 객체 (§4.4) |
| 범위 (range) | 양자화할 때 잘리지 않는 절댓값의 상한 R. 값 x 는 \|x\| ≤ R 이면 양자화 범위 안이고, 넘으면 ±R 로 잘린다 |
| 스케일 (scale) | 양자화 값 1 이 나타내는 실제 값의 크기. 대칭 INT8 이면 R / 127. 이 파일에는 적지 않는다 |
| Cout | 층의 출력 채널 수. conv 는 `out_channels`, linear 는 `out_features` |
| NPU 층 | 실제로 NPU 에서 도는 층. 어느 층을 NPU 로 보낼지는 실행 환경이 정하고, 그중 `fp_keep` 에 있는 층은 뺀다 |
| 변형 | 구조는 같고 가중치만 다른 모델(예: yolo26n 구조의 coco·drone) |
| 정적 / 동적 입력 스케일 | 입력 스케일을 이 파일의 `in.max` 로 고정하는 것(정적) / 실행할 때마다 들어온 입력의 최대 절댓값으로 정하는 것(동적). 어느 쪽으로 돌지는 실행 설정이 정한다 |

## 3. 파일 규칙

1. JSON (RFC 8259), UTF-8 이어야 한다
2. 숫자는 **float64** 로 다룬다
   - 쓰는 쪽은 다시 읽었을 때 같은 float64 값이 나오는 10진 표기로 써야 한다(Python `json` 기본 동작)
   - 읽는 쪽은 float64 로 읽고, 모든 계산을 float64 로 한 뒤 **마지막에 한 번만** 실행에 쓰는 dtype(예: float32)으로 바꿔야 한다
   - NaN·Infinity 는 안 된다
3. 객체 안 칸의 순서는 상관없다. 쓰는 쪽은 어떤 순서로 써도 되고, 읽는 쪽은 순서에 기대면 안 된다
   - `layers` 에 층이 적힌 순서도 모델 실행 순서와 상관없다. 층은 이름으로만 찾는다
   - 배열은 다르다. `out.max` 는 c 번째 값이 채널 c 의 범위라 순서가 중요하다. `fp_keep` 은 순서와 상관없다
4. 모델 패키지 안에서는 파일 이름이 `scale.json` 이어야 한다

## 4. 칸 정의

**이 절에 정한 칸만 쓸 수 있다.** 정하지 않은 칸이 하나라도 있으면 틀린 파일이다. 예외는 `calib` 하나다(§4.3).

### 4.1 최상위

| 칸 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `format` | 문자열 | ● | 반드시 `"fuse_scale_v1"` |
| `model` | 문자열 | ● | 구조 이름 (예 `"yolo26n"`) |
| `variant` | 문자열 | ● | 변형 이름 (예 `"drone"`) |
| `imgsz` | 정수 ≥ 1 | ● | 값을 잰 입력 해상도(정사각 한 변). 이 해상도로 실행할 때만 쓸 수 있다. v1 은 정사각 입력만 다룬다 |
| `weights` | 객체 | ● | §4.2 |
| `calib` | 객체 | ● | §4.3 |
| `act_scheme` | 문자열 | ● | v1 은 반드시 `"symmetric"` (0 을 가운데 둔 대칭 INT8) |
| `out_scale_mode` | `"single"` \| `"per_channel"` | ● | 이 값으로 돌릴 출력 스케일 방식. `single` = 층마다 스케일 하나, `per_channel` = 채널마다 스케일 하나 (§5.3) |
| `fp_keep` | 배열 | ● | §4.5. FP 유지 층이 없어도 `[]` 를 꼭 적는다 |
| `layers` | 객체 | ● | 층 이름 → 층 값(§4.4). 비어 있으면 안 된다 |
| `created` | 문자열 |  | 만든 시각. 권장 ISO 8601 |

### 4.2 `weights` — 값을 잰 원본 가중치

| 칸 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `file` | 문자열 | ● | 가중치 파일 이름(경로 없이) |
| `sha256` | 문자열, 소문자 16진 64자 | ● | 그 파일 바이트 전체의 sha256 |

- 범위를 잴 때 모델에 불러온 **양자화하지 않은 원본 가중치 파일**이어야 한다. 양자화한 가중치 파일 같은 파생 파일은 적을 수 없다
- 저장 dtype 과 파일 형식은 상관없다. 예: ultralytics 체크포인트는 FP16 으로 저장돼 있고 불러올 때 FP32 로 바뀐다. 짝은 `sha256` 으로만 확인한다

### 4.3 `calib` — 어떻게 쟀나

**기록용**이다. 읽는 쪽은 이 칸의 값을 실행에 쓰지 않는다. 아래에 없는 칸도 기록용으로 더할 수 있다(예 `converted_from`).

| 칸 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `tool` | 문자열 | ● | 값을 만든 도구 |
| `tool_version` | 문자열 또는 `null` | | 도구 버전 또는 커밋 |
| `dataset` | 문자열 | ● | 캘리브 이미지 설명 (예 `"VisDrone2019-DET train (정렬 앞 16장)"`) |
| `n_images` | 정수 ≥ 1 | ● | 캘리브 이미지 장수 |
| `images_sha256` | 문자열(소문자 16진 64자) 또는 `null` | | 캘리브 이미지 묶음의 sha256. 아래 정의 |
| `preprocess` | 문자열 | ● | 전처리 구현 이름. 아래 |
| `out_method` | 문자열 | ● | 출력 범위(`out.max`)를 고른 방법의 이름 (예 `"absmax"`) |
| `out_method_args` | 객체 | | `out_method` 의 설정 (예 `{"margin": 1.1}`) |
| `in_method` | 문자열 | ● | 입력 범위(`in.max`)를 고른 방법의 이름 (예 `"observed_absmax"`) |
| `in_method_args` | 객체 | | `in_method` 의 설정 |
| `out_granularity` | `"channel"` \| `"tensor"` | | 출력 범위를 채널마다 쟀나(`channel`), 층 전체에서 하나로 쟀나(`tensor`). 실행 때 쓰는 스케일 방식(`out_scale_mode`)과는 다른 칸이다 |
| `accuracy` | 객체 | | 이 값으로 잰 정확도와 그 조건. 기록용 |

- `images_sha256` = 고른 순서대로 이미지마다 `<파일 sha256>␣␣<파일 이름>` 과 줄바꿈 문자 하나(LF)를 이어 붙인 문자열 전체(UTF-8)의 sha256. `␣␣` 는 공백 두 칸, 마지막 줄 끝에도 LF 를 붙인다(`sha256sum` 출력과 같은 모양). 파일 이름은 디렉터리 경로를 뺀 이름이다
- `preprocess` 는 같은 이름이면 같은 구현을 가리켜야 한다. 이름이 같은 전처리라도 구현이 다르면 범위가 크게 달라질 수 있다. 이 저장소의 YOLO 계열이 쓰는 `letterbox_pil_bilinear` = 가로세로 비율을 유지해 입력 크기 안에 꼭 맞게 PIL BILINEAR 로 크기를 바꾸고(새 크기는 반올림), 회색(114, 114, 114) 정사각 캔버스 가운데에 붙인 뒤 255 로 나눈 RGB(0~1)
- `margin` — 범위에 곱한 여유 배수는 각 방법의 설정에 `"margin": 수 > 0` 으로 적는다. 층 값에 이미 곱해져 있다

### 4.4 `layers` — 층 값

키는 **층 이름**, 값은 아래 객체다.

**층 이름**
- 루트 모듈의 `named_modules()` 이름이어야 한다. BatchNorm 을 앞 conv 에 합친(fuse) 뒤의 모델 기준이다
  - ultralytics: `YOLO(...).model` → `"model.0.conv"`, `"model.22.cv3.0.1.conv"`
  - timm: 모델 객체 자체 → `"layers.0.blocks.0.attn.qkv"`
- 모양: 영문·숫자·`_` 로 된 조각을 `.` 으로 이은 것

**층 값 객체**

| 칸 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `op` | `"conv2d"` \| `"linear"` | ● | 층 종류 |
| `out` | `{"max": 숫자 또는 숫자 배열}` | ● | 출력 범위 |
| `in` | `{"max": 숫자}` | ● | 입력 범위 |

**`out.max` — 출력 범위**
- 값: 양수 하나(모든 채널이 같은 범위) 또는 길이 Cout 의 양수 배열(채널 c 의 범위 = c 번째 값)
- 무엇의 범위인가: BatchNorm 을 합친 FP32 모델에서 그 층이 내는 값 y 다
  - `conv2d`: conv 연산 출력. **bias 를 더한 뒤, 활성함수 앞.** ultralytics `Conv` 블록이면 `.conv` 모듈의 출력이다
  - `linear`: x·Wᵀ. **bias 를 더하기 전** (linear bias 는 NPU 밖에서 FP 로 더한다)
- 범위를 고르는 방법과 margin 을 **이미 적용한 최종값**이어야 한다
- 범위는 양수여야 한다. 관측 범위가 0 인 채널을 어떤 양수로 채웠는지는 `out_method_args` 에 적는다

**`in.max` — 입력 범위**
- 값: 양수 하나. 입력 스케일은 텐서당 하나라 배열이면 안 된다
- 무엇의 범위인가: 그 모듈이 forward 에서 받는 입력 텐서 x 의 양자화 범위. 입력 스케일 = `in.max / 127`
- 범위를 고르는 방법과 margin 을 이미 적용한 최종값이어야 한다
- 정적 입력 스케일이면 이 값으로 고정하고, 동적이면 쓰지 않는다. 정적이면 범위를 넘는 입력이 잘린다

### 4.5 `fp_keep` — FP 유지 층

NPU 에서 빼고 FP 로 계산할 층이다. INT8 로 돌리면 정확도가 크게 떨어지거나, 층 모양이 NPU 가 받는 범위를 넘는 경우 등이며, 이유는 `reason` 에 적는다.

| 칸 | 타입 | 필수 | 뜻 |
|---|---|---|---|
| `layer` | 층 이름 | ● | `layers` 의 키 중 하나여야 한다 |
| `reason` | 문자열 | ● | 남기는 이유. 권장: 근거 수치 |

- 이 목록의 층은 NPU 로 돌리지 않는다
- 그 층의 `layers` 값은 지우지 않고 남겨 둔다

## 5. 값 규칙

### 5.1 범위로 적는다
- 층 값은 스케일이 아니라 범위다. 범위를 스케일·재양자화 배율로 바꾸는 계산은 읽는 쪽이 한다
- 스케일 s 로 결과를 낸 도구는 `max = s × 127` 을 float64 로 계산해 적어야 한다

### 5.2 적힌 값이 곧 쓸 값이다
- margin·클리핑 방법은 층 값에 이미 들어 있어야 한다. 읽는 쪽은 값을 다시 곱하거나 고치면 안 된다

### 5.3 출력 스케일 방식과 `out.max` 모양

| 방식 | `out.max` 배열 | `out.max` 수 하나 |
|---|---|---|
| `single` — 층에 출력 스케일 하나 | 허용. 스케일은 배열 최댓값으로 정한다 | 허용 |
| `per_channel` — 채널마다 출력 스케일 | 허용 | **안 된다** |

### 5.4 어떤 층을 넣어야 하나
- NPU 층은 모두 `layers` 에 있어야 한다
- NPU 로 보내지 않는 층이 들어 있어도 틀린 파일은 아니다. 읽는 쪽이 쓰지 않는다
- 어느 층이 NPU 로 갈지 모르면 모델의 모든 `Conv2d`·`Linear` 를 넣으면 된다

## 6. 검사 규칙

### 6.1 JSON Schema 로 검사하는 것
`fuse_scale_v1.schema.json` 이 아래를 검사한다.
- §4 의 칸 이름·타입·필수 여부, 정하지 않은 칸이 없는지(`calib` 제외)
- `format`·`act_scheme` 고정값, 선택지 칸의 값
- sha256 모양(소문자 16진 64자), 층 이름 모양
- 범위 값이 양수, `in.max` 가 수 하나, `out.max` 배열이 비지 않음
- §5.3 의 `per_channel` + 수 하나 금지
- `in`·`out` 의 `min` 칸 금지 (v1 은 대칭만)

### 6.2 Schema 로는 못 하지만 파일만으로 검사할 수 있는 것
- `fp_keep[].layer` 가 `layers` 의 키여야 한다

### 6.3 모델이 있어야 검사할 수 있는 것 (읽는 쪽이 한다)

| 규칙 | 어기면 |
|---|---|
| `weights.sha256` = 지금 불러온 원본 가중치 파일의 sha256 | 오류 |
| `imgsz` = 지금 실행 해상도 | 오류 |
| `out.max` 배열 길이 = 그 층의 Cout | 오류 |
| `layers` 의 이름이 모델에 없다 | 그 층 건너뜀 + 알림 |

## 7. 버전 규칙

- v1 에는 칸을 더할 수 없다. 더하거나 뜻을 바꾸면 새 형식 이름(`fuse_scale_v2` …)을 쓴다. 예외는 `calib` 안의 기록용 칸이다
- 읽는 쪽은 아는 형식 이름만 받고 나머지는 거부해야 한다

## 8. 검사하는 법

JSON Schema 로 §6.1·§6.2 를 검사할 수 있다.

```python
import json, jsonschema   # pip install "jsonschema>=4.18"

schema = json.load(open("docs/fuse_scale_v1.schema.json", encoding="utf-8"))
doc = json.load(open("yolo26n_coco/scale.json", encoding="utf-8"))
jsonschema.Draft202012Validator(schema).validate(doc)          # 틀리면 ValidationError

# §6.2 — Schema 로 못 하는 것
assert all(f["layer"] in doc["layers"] for f in doc["fp_keep"])
```
